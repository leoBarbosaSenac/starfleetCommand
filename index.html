Starfleet Command

Gerenciamento de uma frota espacial. Naves diferentes, comportamentos diferentes — e um mesmo sistema capaz de lidar com todas elas através de classes, herança e interfaces.

registro de missão · classes abstratas, interfaces e polimorfismo
CONTEXTO

A missão

Você foi contratado para desenvolver um sistema de gerenciamento de uma frota de espaçonaves para uma grande organização de exploração espacial.

A organização possui diferentes tipos de espaçonaves, cada uma com características e comportamentos próprios: naves de exploração, naves de transporte, naves de combate, sondas automatizadas e outros tipos de veículos espaciais.

Apesar de serem diferentes, todas elas precisam participar do sistema de gerenciamento da frota. O problema é que cada tipo de nave funciona de uma maneira diferente:

  • Uma nave de combate pode atacar.
  • Uma nave de transporte pode transportar cargas.
  • Uma nave de exploração pode explorar planetas.
  • Uma sonda pode coletar dados automaticamente.

Além disso, algumas naves podem executar mais de uma dessas funções. Seu objetivo é desenvolver um sistema orientado a objetos capaz de representar essa frota.

OBJETIVOS

O que você vai praticar

  • Classes, objetos, constructors, atributos e métodos
  • Encapsulamento — private e public
  • Getters e setters
  • Herança e classes abstratas
  • Interfaces e implementação de interfaces
  • Uma classe implementando mais de uma interface
  • Uso de objetos através de tipos de interface (polimorfismo)
  • Arrays de objetos e arrays tipados por interface
  • Separação de classes em arquivos e organização de um pequeno sistema

PARTE 1

A classe base — Spacecraft

Crie uma classe chamada Spacecraft. Ela deverá representar uma espaçonave genérica.

🧬 Antes de começar: o que é uma classe abstract?

Pense bem: nenhuma nave da sua frota é "só uma espaçonave genérica". Toda nave real é um Fighter, um TransportShip, um ExplorationShip ou algo do tipo. Spacecraft existe apenas para reunir o que é comum a todas elas — não faz sentido alguém escrever new Spacecraft(...) e criar uma nave "sem tipo".

Uma classe abstrata é exatamente isso: uma classe que serve de base para herança, mas que não pode ser instanciada diretamente. O TypeScript bloqueia qualquer tentativa de new Spacecraft(...) — só é permitido criar objetos das classes filhas, como Fighter ou TransportShip.

Na prática, é só adicionar a palavra-chave abstract antes de class:

TypeScript
abstract class Spacecraft {
    // atributos e métodos normalmente...
}

// ❌ Erro de compilação:
const nave = new Spacecraft(1, "Genérica", 100, 100);

// ✅ Funciona normalmente, porque Fighter herda de Spacecraft:
const caça = new Fighter(1, "Valkyrie", 100, 100, 25);

Tudo o que você já sabe sobre herança continua valendo: extends Spacecraft funciona do mesmo jeito, os atributos e métodos concretos são herdados normalmente. A única diferença é que Spacecraft deixa de ser um objeto que existe sozinho no mundo — ela passa a existir apenas através das suas subclasses.

Uma classe abstrata também pode declarar métodos abstratos — métodos sem corpo, que apenas obrigam cada subclasse a implementar sua própria versão. Isso é opcional neste exercício, mas se quiser ir além, experimente tornar showStatus() abstrato e implementá-lo de forma diferente em cada nave.

A classe deve possuir os seguintes atributos:

atributos
id
name
fuel
health

Utilize encapsulamento. Os atributos não devem ser acessados diretamente de fora da classe:

TypeScript
private id: number;

A classe deve possuir um constructor capaz de receber os valores necessários para criar uma nave, além de getters para consultar os atributos. Exemplo:

TypeScript
getFuel(): number

Crie também métodos para:

métodos
refuel()
takeDamage()
repair()
showStatus()

⚠️ Regras

  • fuel não pode ficar abaixo de 0.
  • health deve permanecer entre 0 e 100.
  • takeDamage() deve reduzir a vida da nave.
  • repair() deve recuperar vida, sem ultrapassar 100.
  • refuel() deve aumentar o combustível.

Crie também um método:

TypeScript
isOperational(): boolean

Esse método deverá retornar true caso a nave tenha vida maior que 0 e combustível maior que 0.

PARTE 2

Interface CombatCapable

Nem toda nave é capaz de combater. Por isso, não seria interessante colocar um método attack() diretamente em Spacecraft.

Crie uma interface chamada CombatCapable. Ela deverá definir o comportamento necessário para que uma nave seja considerada capaz de combate:

TypeScript
attack(target: Spacecraft): number;

O método deve retornar a quantidade de dano causado.

PARTE 3

Interface CargoCarrier

Nem toda espaçonave transporta cargas. Crie uma interface chamada CargoCarrier:

TypeScript
loadCargo(amount: number): void;
unloadCargo(amount: number): void;
getCargoCapacity(): number;
getCurrentCargo(): number;

A capacidade de carga deverá ser definida pela classe que implementar a interface.

PARTE 4

Interface Exploratory

Crie uma interface chamada Exploratory, para representar qualquer objeto capaz de realizar exploração espacial:

TypeScript
explore(location: string): string;
collectData(): string;
PARTE 5

Fighter

Crie uma classe Fighter. Ela deverá herdar de Spacecraft (que agora é abstract — isso não muda nada aqui, a herança funciona normalmente). Uma nave de combate deverá implementar CombatCapable:

TypeScript
class Fighter extends Spacecraft implements CombatCapable

A classe deverá possuir alguma característica específica de uma nave de combate, por exemplo weaponPower. Esse atributo deverá ser encapsulado.

Implemente o método attack(target: Spacecraft): number. O ataque deverá:

  1. Verificar se a nave está operacional;
  2. Calcular o dano;
  3. Aplicar o dano ao alvo;
  4. Retornar o dano causado.
PARTE 6

TransportShip

Crie uma classe TransportShip, herdando de Spacecraft e implementando CargoCarrier. Ela deverá possuir uma capacidade máxima de carga, por exemplo cargoCapacity e currentCargo, ambos encapsulados.

  • loadCargo() deve impedir que a quantidade transportada ultrapasse a capacidade máxima.
  • unloadCargo() não pode permitir que a quantidade de carga fique abaixo de 0.
PARTE 7

ExplorationShip

Crie uma classe ExplorationShip, herdando de Spacecraft e implementando Exploratory. A nave deverá conseguir explorar diferentes locais. Por exemplo:

TypeScript
explore("Mars")

poderia retornar uma mensagem indicando que a nave iniciou uma exploração em Marte. O método collectData() deverá retornar uma mensagem informando que dados científicos foram coletados. A exploração deverá consumir combustível.

PARTE 8

MultiPurposeShip — múltiplas funções

Uma das partes mais importantes do exercício. Crie uma classe MultiPurposeShip, herdando de Spacecraft, mas implementando mais de uma interface: capaz de combate, capaz de transportar carga e capaz de explorar.

TypeScript
class MultiPurposeShip
    extends Spacecraft
    implements CombatCapable, CargoCarrier, Exploratory

Essa classe deverá implementar todos os métodos exigidos pelas três interfaces.

PARTE 9

O verdadeiro propósito das interfaces

Agora crie funções que recebem interfaces como parâmetro, e não classes específicas.

TypeScript
function startCombat(ship: CombatCapable, target: Spacecraft): void

Essa função deverá utilizar ship.attack(target). Observe que a função não deve receber Fighter — ela deve receber CombatCapable. Isso significa que qualquer objeto que saiba executar attack() poderá ser utilizado.

TypeScript
function transportCargo(
    ship: CargoCarrier,
    amount: number
): void

Essa função deverá utilizar os métodos definidos pela interface CargoCarrier.

TypeScript
function performExploration(
    ship: Exploratory,
    location: string
): void

Ela deverá utilizar ship.explore(location) e ship.collectData().

PARTE 10

O conceito importante

Agora teste algo interessante. Crie uma nave de cada tipo:

TypeScript
const fighter = new Fighter(...);
const transportShip = new TransportShip(...);
const explorationShip = new ExplorationShip(...);
const multiPurposeShip = new MultiPurposeShip(...);

Depois: startCombat(fighter, transportShip) — isso deve funcionar porque Fighter implements CombatCapable.

Agora faça startCombat(multiPurposeShip, fighter). Também deve funcionar, pelo mesmo motivo: MultiPurposeShip implements CombatCapable.

Teste ainda performExploration(explorationShip, "Mars") e performExploration(multiPurposeShip, "Jupiter"). Ambos devem funcionar. O sistema não precisa saber se recebeu uma ExplorationShip ou uma MultiPurposeShip — ele só precisa saber: "esse objeto é capaz de realizar exploração?" Essa é uma das principais utilidades das interfaces.

PARTE 11

Interface como tipo

Crie um array de naves capazes de combate e adicione as naves compatíveis:

TypeScript
const combatShips: CombatCapable[] = [];

combatShips.push(fighter);
combatShips.push(multiPurposeShip);

Faça o mesmo para naves exploradoras (Exploratory[]) e para naves capazes de transportar carga (CargoCarrier[]). Observe que esses arrays não precisam conhecer as classes concretas — eles trabalham apenas com os contratos definidos pelas interfaces.

PARTE 12

Uma nave pode estar em vários grupos

A mesma multiPurposeShip deverá poder ser adicionada aos três arrays, porque implementa as três interfaces:

TypeScript
combatShips.push(multiPurposeShip);
explorationShips.push(multiPurposeShip);
cargoShips.push(multiPurposeShip);
CombatCapable CargoCarrier Exploratory │ │ │ ├── Fighter ├── TransportShip ├── ExplorationShip └── MultiPurposeShip └── MultiPurposeShip └── MultiPurposeShip

Imagine que cada interface representa uma capacidade. Uma classe pode possuir várias capacidades ao mesmo tempo.

PARTE 13

Uma interface mais completa — Repairable

Crie uma interface Repairable, representando qualquer objeto que possa ser reparado:

TypeScript
repair(): void;
getRepairCost(): number;

Pense: quais classes deveriam implementar essa interface? Você pode decidir quais objetos do sistema possuem essa capacidade e implementar a interface nas classes adequadas.

PARTE 14

Interfaces não são classes

Crie uma função repairObject(object: Repairable): void que execute object.repair(), e teste com objetos que implementam Repairable.

PARTE 15

Interfaces e encapsulamento

Imagine que você tenha:

TypeScript
interface SpacecraftInfo {
    id: number;
    name: string;
}

class Fighter implements SpacecraftInfo {
    private id: number;
    private name: string;
}

O TypeScript apresentará um erro. Explique por que isso acontece — e depois altere a solução para que a classe continue utilizando encapsulamento. Uma possibilidade é utilizar métodos:

TypeScript
interface SpacecraftInfo {
    getId(): number;
    getName(): string;
}

A classe poderá manter private id: number e private name: string, fornecendo getId() e getName() como forma pública de acesso.

💬 Pergunta

Qual é a vantagem de a interface exigir getId(): number em vez de id: number? Explique com suas próprias palavras.

PARTE 16

Interface como contrato

Uma classe que implementa uma interface pode armazenar seus dados da maneira que quiser. Fighter pode guardar weaponPower, enquanto MultiPurposeShip pode guardar laserLevel e energy — implementações diferentes, mesmo contrato: CombatCapable.

💬 Para responder

Por que isso é útil? Por que function startCombat(ship: CombatCapable, target: Spacecraft) é mais flexível do que function startCombat(ship: Fighter, target: Spacecraft)?

PARTE 17

Sistema completo de gerenciamento — Fleet

Crie uma classe Fleet, responsável por gerenciar todas as espaçonaves. Ela deverá possuir uma coleção de Spacecraft[] e os métodos:

TypeScript
addShip(ship: Spacecraft): void;
removeShip(id: number): void;
findShip(id: number): Spacecraft | undefined;
showFleet(): void;

Utilize encapsulamento — a lista de naves não deve ser diretamente acessível de fora da classe.

PARTE 18

Buscar por capacidade

Adicione à classe Fleet métodos capazes de retornar apenas determinadas capacidades:

TypeScript
getCombatShips(): CombatCapable[]
getCargoShips(): CargoCarrier[]
getExplorationShips(): Exploratory[]

Você deverá analisar as naves armazenadas e identificar quais implementam cada capacidade. Uma nave pode aparecer em mais de uma categoria.

PARTE 19

main.ts

No arquivo main.ts, crie uma frota contendo pelo menos:

  • 2 Fighter
  • 2 TransportShip
  • 2 ExplorationShip
  • 1 MultiPurposeShip

Depois:

  1. Exiba todas as naves;
  2. Realize pelo menos um combate;
  3. Transporte algumas cargas;
  4. Realize uma exploração;
  5. Cause dano em uma nave;
  6. Repare uma nave;
  7. Recupere combustível;
  8. Liste as naves de combate;
  9. Liste as naves de transporte;
  10. Liste as naves de exploração.
DESAFIO ADICIONAL

Sistema de capacidades

Imagine que sua organização espacial queira adicionar novas capacidades no futuro. Crie as interfaces Refuelable, Scannable e Dockable, cada uma definindo um comportamento específico.

Crie pelo menos uma classe que implemente uma dessas interfaces, e depois uma função que receba essa interface como parâmetro. Por exemplo:

TypeScript
function scanObject(object: Scannable): void

A função não deve saber qual é a classe concreta do objeto — ela só precisa saber que o objeto é Scannable.

DESAFIO FINAL

Projeto aberto — SpaceDrone

Imagine que amanhã a organização compre uma nova tecnologia de drones espaciais. Crie uma classe SpaceDrone. Esse drone não precisa necessariamente herdar de Spacecraft. Entretanto, ele deverá ser capaz de explorar, coletar dados e escanear objetos — faça-o implementar as interfaces necessárias.

Depois utilize performExploration(...) com o seu SpaceDrone.

🔍 Observe algo importante

Se funcionar, significa que performExploration(ship: Exploratory, location: string) não está interessada em saber se recebeu um ExplorationShip, um MultiPurposeShip ou um SpaceDrone. Ela só está interessada em saber: "esse objeto implementa Exploratory?"
